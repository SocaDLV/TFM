# LLM-NoC Co-Simulation Framework

![C++](https://img.shields.io/badge/C++-17-blue.svg)
![Python](https://img.shields.io/badge/Python-3.8+-yellow.svg)
![License](https://img.shields.io/badge/License-MIT-green.svg)

A cycle-accurate, scientifically rigorous co-simulation environment designed to evaluate the physical network bottlenecks of Large Language Models (LLMs), with a specific focus on **Mixture of Experts (MoE)** architectures like Mixtral.

This project merges the compute-graph fidelity of **LLMSimulator** with the flit-level network contention modeling of **BookSim2**, utilizing an automated Python CLI workflow for reproducible scientific analysis.

---

## 📖 Abstract & Motivation

While current LLM simulators accurately model silicon compute time (Roofline models) and static network latency ($Time = Data / Bandwidth$), they often fail to capture the dynamic, asymmetrical network traffic generated by MoE routing. When tokens route to specific experts across different GPUs (Expert Parallelism), it creates bursts of traffic that saturate physical interconnects, introducing hidden tail latencies.

This framework solves this by introducing an **"Oracle" integration model**:
Instead of analytical formulas, the compute simulator delegates all `AllReduce`, `AllToAll`, and `moe_gather`/`scatter` primitives to a BookSim2 backend. BookSim2 resolves topology constraints, Virtual Channel (VC) allocation, and flit-level collisions, returning exact nanosecond latencies that induce real `NETWORK_STALL` events in the cycle-accurate trace.

## 🏗️ Architecture & Contributions

* **Compute Engine:** Models modern architectural features like Grouped Query Attention (GQA), SwiGLU activations, and MoE routing on homogeneous hardware (e.g., Nvidia B100).
* **Network Engine:** Evaluates physical network topologies (Torus, Mesh, Ring) and routing algorithms (Dim-Order).
* **Architectural Corrections:** Several critical bugs from the baseline simulators were patched for scientific validity:
    * Fixed MoE decoder memory leaks by correcting `LayerNorm`/`Residual` module instantiation.
    * Enforced synchronization barriers in SwiGLU 3-way FFN dependency chains.
    * Removed unconditional clock overwrites in the timeboard to allow accurate asynchronous timing reporting.

## 🚀 Usage: Automated CLI Workflow

The framework provides a robust Python wrapper (`run_sim.py`) that orchestrates the simulation, automatically calculates node capacities, and securely collects trace artifacts.

Run simulations directly from the root directory:

```bash
# Example 1: 1D Ring Topology (8 GPUs)
python run_sim.py --model mixtral --net_dims 8 --topology torus

# Example 2: 2D Mesh Topology (4x4 = 16 GPUs)
python run_sim.py --model mixtral --net_dims 4 4 --topology mesh

# Example 3: Enable Packet Tracking Debug Mode
python run_sim.py --model mixtral --net_dims 2 2 2 --topology mesh --debug_pids
```

### CLI Parameters

#### Network Architecture Options (BookSim2)
| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `--topology` | `str` | `torus` | Physical interconnect topology (`torus`, `mesh`, `ring`). |
| `--net_dims` | `int(s)` | `8` | Spatial dimensions. Single int for 1D (e.g., `8`), multiple for 2D/3D (e.g., `2 2 2` for a 3D grid). Must be symmetrical. Total GPUs are inferred automatically. |
| `--routing` | `str` | `dim_order` | Routing algorithm (`dim_order`, `min_adapt`). |
| `--vcs` | `int` | `4` | Number of Virtual Channels. *Note: Torus requires >= 2 to prevent deadlocks.* |

#### Workload & Model Options (LLMSimulator)
| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `--model` | `str` | `mixtral` | Target LLM Architecture (e.g., `mixtral`, `llama`). |
| `--input_len` | `int` | `1024` | Prompt size. Dictates the initial memory/compute prefill burst. |
| `--output_len`| `int` | `10` | Number of tokens to generate per iteration. **Higher values induce more steady-state network contention.** |
| `--batch_size`| `int` | `32` | Maximum batch size for continuous batching scenarios. |
| `--iter` | `int` | `5` | Number of times to repeat the simulation for statistical variance. |

#### Simulation Execution & Debug Options
| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `--parallel` | `flag` | `False` | Enables parallel compute execution (xPU+PIM heterogeneous setups only). |
| `--data_mode`| `str` | `synthesis` | Compute timing mode (`synthesis` for trace-based, `analytical` for Roofline). |
| `--gantt` | `flag` | `False` | Exports Gantt chart rendering data for visualization. |
| `--debug_pids`| `flag` | `False` | **NEW:** Intercepts BookSim2 tail-flit retirements to export a `packet_tracking_debug.csv` file, necessary for tracking overlapping packet lifecycles. |

## 📊 Automated Trace Analysis

The framework includes an automated data analysis script (`analyze_traces.py`) that parses the cycle-accurate `.trc` logs generated by the co-simulator. It separates pure GPU compute time from physical network overhead.

```bash
# Analyze the 3 most recent simulations
python analyze_traces.py
```

### Output Artifacts (Visualizations)
Results are saved in a newly generated timestamped folder inside `build/analysis/`.
* **`anatomia_latencia.png`**: A stacked bar chart breaking down inference latency into: Compute Time, Network Transit Time, and Network Stalls.
* **`desglose_primitivas_moe.png`**: A focused bar chart comparing the network cost of specific MoE routing primitives (`moe_scatter` vs `moe_gather`).

## 📈 Network Congestion Visualization (Packet Tracking)

To empirically prove the effects of "Queueing Delay" and "Head-of-Line Blocking" within the NoC, the framework includes a packet-tracking visualizer (`plot_packet_tracking.py`). It requires simulations to be run with the `--debug_pids` flag.

```bash
# Generate sliding window Gantt charts of packet lifecycles
python plot_packet_tracking.py build/results/[your_simulation_folder]/ --samples 50
```

### Output Artifacts
This script parses the `packet_tracking_debug.csv` and outputs three crucial visualizations to demonstrate progressive physical congestion:
* **`gantt_1_fase_libre.png` (Free Phase):** Shows the first injected packets crossing the empty network with minimal free-space latency.
* **`gantt_2_congestion_media.png` (Medium Congestion):** A sequential snapshot centered around the first packet to exceed 1,500 clock cycles, visually demonstrating the "staircase" effect of packets waiting in Virtual Channel queues.
* **`gantt_3_congestion_critica.png` (Critical Bottleneck):** A snapshot centered around packets exceeding 2,000 clock cycles, illustrating severe structural bottlenecks caused by massive MoE All-To-All bursts.

## ⏱️ Cycle-to-Cycle GPU Timeline (Chronogram)

To validate the Bulk Synchronous Parallel (BSP) model and guarantee strict physical causality, the framework can render a global micro-architectural timeline of all GPUs using `plot_cronograma.py`.

```bash
# Generate chronological windows of the cluster's state
python plot_cronograma.py build/results/[your_simulation_folder]/ --window 100000
```

### Output Artifacts
The script automatically generates sequential images inside a `cycle-to-cycle/` subdirectory, breaking the simulation down into readable temporal windows (e.g., 100,000 nanosecond slices).

It plots a horizontal timeline for each GPU, color-coded by execution state:
* 🟢 **Green (Calc):** Pure Compute (`POP_OPERATION` like QKV, MLP, Attention).
* 🟦 **Blue (Scatter/Gather):** Network communication via BookSim2.
* 🟥 **Red (Stall):** Idle GPU time waiting at a global synchronization barrier due to load imbalance (`NETWORK_STALL`).

These visualizations perfectly capture the cyclic nature of Transformer layers and empirically demonstrate the asynchronous behavior leading to network stalls.
